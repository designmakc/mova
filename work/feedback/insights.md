# Insights intake — open

> The standing collection point. The retro playbook appends here whenever a session finds
> something about the **workspace** worth changing that it could not responsibly fix on the
> spot. A housekeeping pass drains it, decides what actually changes, and archives what it
> triaged into a dated file next to this one.
>
> **What belongs here:** anything that changes a rule, trades one design against another,
> spans several files, or that the finding session was not confident enough to decide alone.
> **What does not:** anything with an obvious home — a transfer hook, a learner-profile fact,
> a coded error, a missing ledger note. Those get fixed in the session that found them.
>
> **Contributors do not filter for novelty or feasibility.** Whether something is already
> half-implemented, or contradicts another block, is the triage session's problem. Suppressing
> a real observation because it looks handled is the one failure that loses it permanently.
> Several retros normally run at once and file the same finding independently — that
> convergence is evidence, and merging it is triage's job, not yours.
>
> Closed cycles, newest first: none yet.

## How to append (do not edit this file by hand)

Sessions write here concurrently, and an editor-tool write silently drops whichever block
landed second. Draft your block to a scratch file outside the repo, then:

```bash
scripts/feedback.sh "<source label>" --file <path to your block>
```

The script takes an atomic lock, assigns the next `FB-NNN`, stamps source and time, and
appends. You own only the block you appended — never edit another, or this header.

**Two rules the file enforces** (`work/feedback/insights.test.ts`, and the script's own
guard — both learned the hard way in the reference instance):

- **No `## FB-` heading inside your body.** The script owns the id and numbers from the highest
  one present, so a guessed heading in a body burns ids — `FB-008` through `FB-010` were lost
  that way (limba, 2026-08-12). Your sub-headings are `###`.
- **Make the source label identify you** — `SES-016 retro (lesson)`, not `retro`. Several
  blocks land in the same minute and the label is all triage has to tell them apart.

Block shape (keep the headings, fill them your way):

```markdown
**Session.** What this session was and what it did, in two or three lines.

**Asked / corrected.** What the learner explicitly asked for, pushed back on, or
corrected — including anything already acted on.

### Insight — <one-line claim>

- **Evidence.** The concrete moment. Quote the learner where you can.
- **Insight.** What it implies about how the workspace should work.
- **Lands near.** Best guess at the file or mechanic. Low confidence is fine.
- **Tag.** `[asked]` learner-originated · `[observed]` you noticed it yourself ·
  `[friction]` cost time and shouldn't have.
```
