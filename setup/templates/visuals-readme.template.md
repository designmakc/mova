# work/visuals/ — generated visual teaching artifacts

> **This folder is the site.** What is committed here is what the learner reads — from
> disk and, when publishing is configured, deployed as-is. All conventions (tokens,
> components, audio, reveal machinery, the authoring checklist) live in one place:
> [../../docs/visual/SPEC.md](../../docs/visual/SPEC.md). Start every page from
> [../../docs/visual/starter.html](../../docs/visual/starter.html); validate with
> `node scripts/visualcheck.mjs <file>`.
>
> `index.html` is the hub (generated by `scripts/hub.mjs` — never edited, never indexed
> below). `deck.html` is the drill deck (generated by `scripts/deck.mjs`). The table
> below is the source of truth for what exists: **every authored visual gets its index
> row in the same session that creates it** — `docs/visuals.index.test.ts` fails CI if a
> committed visual has no row here. Superseded visuals keep their file and get
> "(superseded by …)" in their row.

## Retired claims

When the workspace corrects a claim it once taught, the correction-sweep
(`docs/mechanics/teaching.md`) updates the live pages in the same session — and a row
here backstops it forever: wordings the workspace has corrected must not survive in live
pages, because the learner re-reads pages long after the chat transcript dies, and a
stale page outvotes a correct chat. `scripts/visualcheck.mjs` reads this table and fails
any page whose visible text matches a pattern.

Add a row when you retire a wording; rows are permanent — a retired claim reappearing in
a new or regenerated visual is exactly what this catches. The first cell is a JavaScript
regex in backticks, slash-delimited with optional flags (for example an entry reading
backtick, `/no anchor (in|anywhere)/i`, backtick). It runs against the page's visible
text, line by line — markup, styles and scripts are stripped first.
